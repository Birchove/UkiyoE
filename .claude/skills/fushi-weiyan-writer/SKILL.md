# 浮世微言 · 条目写作规范

「浮世微言」是为这个时代留下的一部民间史/笔记体网站,取法《世说新语》《笑林广记》《东京梦华录》等。**第一要义是真实客观**(它首先是「史」);每条分「记事」与「微言」两部分,笔法与立场严格分开。

---

## 0. 两条心法(最重要)

1. **先求全,后求约。** 动笔前,先把对象**尽可能全面**地了解清楚——正反、雅俗、官方与民间、生前与身后——占有的材料要**远多于**成文;成文时再删减、组织、提炼。切忌只读一两篇官方报道就下笔。
2. **记事求其真,微言见其义。** 记事客观,微言见态度;两者不可混用(详见 §3、§4)。

---

## 1. 选题:值不值得写

收录对象应符合(详见 `filter_rules.txt`、`CLAUDE.md`):
- 反映时代风貌、体现时代特征,或针砭时弊;
- 饶有趣味、足资谈助(可收市井笑谈、低俗笑话,但**拒绝速生速朽的烂梗**);
- **做民间史,不做共和国史**——宏大人物(尤其涉政者)**一律不录**;
- 不限人物:一事、一物、一现象、一风物皆可成篇。

**过滤**(一律不录):花边八卦、政治新闻、无意义的热搜、涉政宏大人物。

---

## 2. 考据:求全(决定记事能否立得住)

- **多源,且必含非官方来源。** 官方媒体/新闻的信息往往**被"清洗"过、偏克制**,撑不起立体的"史"。务必兼采:
  - 官方:主流媒体、讣告、通报;
  - **民间:微博、知乎(问答/专栏)、B站(视频/弹幕/评论)、贴吧、抖音、自媒体、社区讨论、悼念帖、二创**。
- **正反都查。** 要客观并列正反,前提是**先把正反双方的事实都搞清楚**。
- **一手优先:** 本人言论/视频/直播/微博 > 媒体转述 > 自媒体转述。
- **存疑必标:** 无法核实的明确标注;数字、引语注明**口径与时点**;**绝不编造**引语、数据或帖子。
- **「史」贵全貌,不避丑言:** 客观记录意味着采集一切——包括批评、争议、负面评价、民间揶揄甚至粗鄙之语。描写时以学术/中性方式呈现机制与各方观点,不渲染、不孤立重复、不预设立场,**但也不回避——回避即失真,全貌方能真了解**。搜集不代表赞同,客观不代表冷漠。
- **善用优质来源:** 优先参考**知乎高赞回答、有代表性的社区讨论、媒体报道的反方声音**等。网络搜索(WebSearch)可检索到大量非官方素材,对敏感话题有时比 subagent 更有效(后者可能触发 API 内容过滤)。
- **做法建议:** 先由主进程或 agent 并行深挖、返回**结构化素材**(事实/时间线/多方观点/趣闻金句/民间反应/来源),再由执笔者**删减组织、融入叙事、提炼微言**。人物条目尤须"由一人见一世"——可于记事末段单开一节**社会反思**(以"论者指出""这场争论照见了……"的口吻记录社会舆论,不同于微言的个人评价)。

---

## 3. 记事:记录事件本身

- **文体:白话文。**
- **立场:客观克制,不含情绪与评价,不预设结论。**
- **篇幅要充实。** 把来龙去脉、关键节点、具体细节、多方说法**写足**——宁详勿略;但须**有组织、有叙事**,不是材料堆砌。
- **争议须并列各方**:用「**誉之者**以为…… / **毁之者**以为……」之类句式,标明各方论据,使读者自辨。
- **信息密度:** 引用具体言论、数据、事件以增其信,但须有据、可追溯。
- **民间的梗化、符号化、二创、悼念**也是「民间史」的一部分,可客观记入(如某人被民间抽象为某些符号)。
- 可参考媒体报道,但须**核实、转述,不照搬**。

## 4. 微言:总结评价(点题之笔)

- **文体:统一为文言**(浅近文言 / 明清笔记体,如《世说新语》、《聊斋》之「异史氏曰」),典雅而可读。
  - **切忌文白夹杂**(此前"半白半文言"的尝试效果不佳,已弃用)。
  - **微言忌一切现代词汇,即便是引用或加引号的专名亦显割裂。** 现代概念与专名须**化用为文言**,例如:社达→「以世为战场」/「物竞天择之说」;信息→「门径」;灯塔→「津梁」;贩卖焦虑→「鬻忧牟利」;微博→「其所书」;雪碧/巧乐兹等品牌名→「借其名之雪字,托物为谑」(描述其象而不呼其名);"死法愿猝死"→「尝言愿得暴卒」;"这辈子很值"→「自谓此生无憾」;AI→「机巧」。**核心原则:宁可迂回描摹,绝不直接嵌入。**
  - 专有名词(人名、地名、书名)可直接入文,其他一律从文言。句式取法古文:判断句、倒装、虚词(之乎者也、矣哉、夫、盖)、四字句、对偶,皆可适度运用,但以**自然流畅、能读懂**为度,不堆砌生僻字。
- **发语词:统一以「微言曰」领起。** 页面会自动加上「微言曰」与印章样式,故 **frontmatter 的 `weiyan` 字段里不要写"微言曰"**,直接写评语正文。
- **立场:可有情绪、可褒贬**,见态度、见思辨。
- **篇幅:数句至一小段**,贵在"微言大义",忌冗长。
- **取法:** 仿「太史公曰」「异史氏曰」,于叙事之外发议论;可借古语点睛(如"防民之口,甚于防川""道高一尺,魔高一丈")。

### 文言自检十则(微言生成后强制执行)

每次微言写就,须逐条过检:

1. **去浮词** — 删四字排比堆砌;删冗余修饰词("特""殊""尤为""诚然"等);一字能尽则不用二;宁简勿缛。
2. **去翻译腔** — 查杀"在…之时代/背景下""就…而言""从…来看""本质上是""值得注意的是""某种程度上""事实上"等现代句式;改"那个/这种"为"彼/此/斯";改"既……又……"为"……而……"或不标关联词。
3. **辨虚词** —
   - 「矣」≠「也」:矣=已然/将然(动态变化),也=判断/解释(静态断定)。
   - 「耳」=仅此而已(限止),「焉」=于之/于此(兼词),「乎」=疑问或轻感慨,「哉」=强烈感叹,「耶/与」=疑问。
   - 「夫」用于句首发端,不用于句中;「盖」=大概(表推测)。
   - 「者」=……的人或事,「之」=属格或宾语,「其」=第三人称领格/指示词。
4. **绝白话残余** — "的/地/得/了/着/过/吗/呢/吧/啊"不出现;"是……的"句式不出现;进行态的"在+"改"方""适"或不标;"被"字被动态尽量改为主动/意动。
5. **单字为骨** — 现代双音动补("进行""发生""实现""通过")→单字("行""生""至""以");动词前不挂"来/去";"作出了/进行了"→单动词。
6. **连接词从古** — 因此/所以→故/是以;但是/但→然/然而;如果→苟/若;而且→且/况;虽然→虽/纵;然后→而后/乃;或者→或;因为→以/为。
7. **无现代指代** — 不出现"他/他们/这个/那个";用"其/之/此/彼/斯/是";"有人"→"或"。
8. **量词从略** — 汉语可略量词,或用"一+X"(一味、一隅、一端、一时)。
9. **骈散相间** — 四字句偶用有节奏,连用不过二三,夹以散句疏气;笔记体以散句为主。
10. **专名从权,新词化用** — 人名/地名/书名可直用;其余现代概念需化用为文言(如"AI"→"机巧","大数据"→"术数","内卷"→"竞逐日烈")。**宁可描其象,不呼其名。**

> 上述自检与"忌一切现代词"的总体原则互为表里:总体原则=写时绝不嵌入;十则=写后逐条打磨。

**微言示例(按十则打磨后):**
> 张生起寒微,以舌耕为业,鬻进身之阶于寻常百姓家,贫者德之,以为引路。然其言也,目文史数理为畏途,绌文史而以谋食尽谋道,识者讥其计功利而已,以胜负断一切,不复问是非,盖视世为战场,而亦以之自绳焉。终岁无休,一「累」字屡见其所书,日驰不辍,虽知暴卒可畏,犹以身试之。昔尝言愿得暴卒,期在不久,又自谓此生无憾,至是乃验,闻者悲之,以为谶。及其殁也,民间初则巷哭以送,继而借其名之「雪」字,托物相谑,甚且效其致死之由以为戏,封神与解构,转掌间耳,悲夫!誉之者以为寒门之津梁,毁之者以为鬻忧牟利之徒,二者皆是,亦皆非也。争者张生,病者实世。此问不在张生,在渴公平而困功利之世也。

## 5. frontmatter 规范

每个条目 = `src/content/entries/<slug>.md`;**文件名即 slug / URL**(用英文或拼音,如 `zhangxuefeng.md` → `/entries/zhangxuefeng/`)。schema 见 `src/content.config.ts`。

```yaml
---
title: "条目标题(可适度文言化)"
category: "figures"        # figures 人物 / events 时事 / customs 风物 / humor 笑语
tags: ["标签一", "标签二"]
event_date: "2026"         # 事件时间或时间跨度,如 "2016-2026"
recorded_date: "2026-07-22"
sources:                   # 务求可追溯;一手优先
  - name: "来源名"
    url: "https://…"
    note: "一句话说明(可选)"
figures: ["涉及人物"]
controversial: true        # 若 true,记事必须并列多方观点
status: "published"        # draft / review / published;仅 published 上站
summary: "一句话提要,用于列表卡片。"
weiyan: |                  # 微言正文,统一文言;不要写"微言曰"
  此处写评语……
---

（正文 = 记事:白话、客观、篇幅充实）
```

---

## 6. 工作流:写稿 → 审核 → 发布

1. 在 **`_drafts/`**(git 忽略,**不进 GitHub**)写稿;
2. 对照 §7 自检;
3. 确认后移入 **`src/content/entries/`**,设 `status: published`;
4. `npm run build` 构建;手动推送 `gh-pages` 部署(无自动部署)。

> `data/`(爬取候选 JSON)与 `_drafts/`(未确认稿件)均已被 `.gitignore` 排除,**不会**上传 GitHub。

---

## 7. 发布前自检清单

- [ ] 记事**篇幅充实**、来龙去脉清楚?(不可偏短)
- [ ] 是否**多源**(含民间/非官方),而非只靠官媒?
- [ ] 记事是否**客观克制、无情绪评价**?争议是否**并列多方**?
- [ ] 微言是否**统一文言、无文白夹杂**?`weiyan` 字段里**没有**多余的"微言曰"?
- [ ] 微言是否**有态度、有深度、不空洞**?
- [ ] `sources` 齐备、可追溯、标注了可靠性?
- [ ] frontmatter 必填字段完整、`status` 正确?
- [ ] 符合选材原则、未触犯过滤黑名单?

## 8. 常见陷阱(前车之鉴)

| 陷阱 | 表现 | 对策 |
|---|---|---|
| **空洞** | 只读一两篇官媒就写;记事三言两语;微言泛泛 | 先求全、多源、写足细节与多方 |
| **只靠官媒** | 信息被清洗、偏克制,无法立体呈现正反 | 兼采微博/知乎/B站/社区/自媒体 |
| **文白夹杂** | 微言"文不像文,白不像白" | **统一文言**;专名直入,口语词勿入句式 |
| **预设立场** | 记事里夹带评价 | 记事客观,评价一律留给微言 |
| **编造** | 杜撰引语/数据/帖子 | 存疑必标,注明口径与时点 |
| **流水账** | 材料堆砌无叙事 | 删减组织,求叙事与思辨 |
| **微言嵌现代词** | 即便用引号括住(AI、社达、雪碧、巧乐兹),读来仍割裂 | 化用为文言:描其象不呼其名,迂回胜于直嵌 |
| **避丑失全** | 因羞于记录"不好"的言论而选择性遗漏 | "史"贵全貌;描写中性、不回避,全貌方能真了解 |
